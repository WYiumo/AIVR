# 功能需求：

## 一般用语描述

​	本项目的最终目标是实现用户在VR中，通过语音的方式生成3DGS物体和数字人，并与其交互。

​	现阶段需要完成VR前端应用的构建，生成3DGS物体和数字人不由前端处理，前端负责语音和VR交互、及其场景渲染。	

​	从给用户的操作流程上来说，用户在 VR 游览器中打开我们的网页应用后需要一个开始界面——这个界面是HTML页面，提供用户进入3D空间的按钮，以及更换初始场景<span style="vertical-align:sub; color:#330000;">[设定1：初始场景]</span>的方式——初始场景的选择以图片作为按钮，用户点击更换，后点击进入3D空间的按钮。用户进入3D空间后可以以6DoF移动视野，控制左右两个VR手柄——手柄需要有镭射，以扳机为方向。用户在佩戴VR头显的情况下移动空间比较有限，需要实现额外的移动方式<span style="vertical-align:sub;">[设定2：额外移动]</span>，以实现在3D空间的自由行动。用户可以按下手柄按键——如左手Y键，打开一个3DUI于相机视野前的特定位置<span style="vertical-align:sub;">[设定3：3DUI面板及其视野位置]</span>，这个3D面板需要有语音输入模块、3D资产列表。用户完成语音输入后，加载相应的3DGS模型到用户前。3D模型加载到场景后，用户可以用手柄镭射选中并对其进行操作——包括手柄跟随移动、3维独立旋转、与其他3D模型组合。

### 设定3：3DUI面板及其视野位置

​	用户在按下左手Y键后，在左手手柄entity的前方放置一个工具轮盘（如下图——轮盘分为四个分区，其中三个颜色为红黄蓝的分区分别代表语音输入、物体操作、定向移动，扇形圆心角为60度，灰色分区不提供功能。），用户每次左右移动摇杆轮盘按方向旋转60度，用户按下右手A键后以确定切换到分区所表示的交互模式。轮盘的旋转需要限定死区，用户不能旋转到灰色的分区。

# 架构设计：



​	playcanvas中需要着重了解的相关api：Application、Scene、Entity、Asset、Script、Layer、Material、Texture、Picker、EventHandler、CameraComponent、ElementComponent、GSplatComponent、GamePad、Xr..等相关类，这些api使用的可能性较高需要优先学习。

```
src/
├── main.ts                  # 创建playcanvas应用、初始化AIVR应用
├── app.ts                   # App 类（薄协调器）
│
├── app/                     # 核心协调层
│   ├── index.ts             # 
│   ├── scene.ts             # Scene 管理器
│   ├── vr-manager.ts        # VR 会话管理
│   ├── asset-manager.ts     # 资源预加载
│   └── font-manager.ts      # 字体管理（单例）
│
├── entities/                # 3D 实体封装
│   ├── ground.ts            # 地面
│   ├── sky.ts               # 天空
│   ├── controller.ts        # VR 手柄控制器
│   └── splat-loader.ts      # 点云加载器
│
├── interaction/             # 交互系统
│   ├── grabbable.ts         # 可抓取标签
│   ├── grabbable-registry.ts # 可抓取注册表 + 拾取
│   ├── xr-picker.ts         # XR 射线拾取器
│   ├── manipulator.ts       # 抓取/旋转操纵器
│   ├── highlight-box.ts     # 抓取反馈
│   └── interaction-manager.ts # 交互协调器
│

│   ├── vr-button.ts         # VR 入口按钮
```
